# Strict lint: zero diagnostics (21 November 2026)

Section D of `docs/project-review-20261121.md` found that strict clippy had never
passed. This note records what was changed so that it does, what was allowed on
purpose, and the one command a release gate runs.

## The gate

```powershell
cargo clippy --workspace --all-targets --locked --features relay-client/native-rtc,relay-client/audio-bench -j 4 -- -D warnings
```

It must exit 0. Notes for whoever runs it:

- Build environment as in `docs/superpowers/plans/2026-10-29-audio-suppressor-round2.md`
  (Global Constraints): `vcvars64`, cmake on `PATH`, `CMAKE_POLICY_VERSION_MINIMUM=3.5`,
  `LK_CUSTOM_WEBRTC`.
- `native-rtc` is the shipped configuration. `audio-bench` is the developer tool in
  the same crate (`required-features`), so without the second feature its target is
  never linted. The `iroh` feature of the client is off in the shipped build and is
  not part of this gate.
- `-D warnings` applies to the six workspace crates only. The patched crates under
  `vendor/` still print their own warnings (livekit 24, serenity 3, eframe 3 at the
  time of writing) and do not fail the command; they are not edited.
- Cargo also prints `file ... main.rs found to be present in multiple build targets`
  for `relay-client`. That is the deliberate design of the `audio-bench` binary (it
  is the client's own module tree with a second entry point, see the comment in
  `crates/relay-client/Cargo.toml`). It is a Cargo manifest warning, not a lint, and
  does not affect the exit code.

## Toolchain pin

`rust-toolchain.toml` pins channel `1.97.1`, components `clippy` and `rustfmt`, target
`x86_64-pc-windows-msvc`, profile `minimal`. The machine already had rustc 1.97.1 as
the rolling `stable` toolchain; rustup treats a pinned `1.97.1` as a different
toolchain name and installed it once on first use (about five components, a few
hundred MB under `~\.rustup\toolchains`). After that `cargo metadata --offline`
resolves with it. A machine without network access needs that toolchain installed
beforehand (`rustup toolchain install 1.97.1 --profile minimal -c clippy -c rustfmt`).
Moving to a newer compiler is now an explicit commit that changes this file; new
clippy lints then arrive together with that commit and not by surprise.

Assumption (the instruction was to decide and write it down): `profile = "minimal"`
plus the two named components, because the build never needs `rust-docs`.

## What was done, by family

Commits: `4b27b4d` (toolchain pin), `4e867d6` (protocol and updater), `98f3997`
(server), `6b0aeb8` (client).

- **Code nothing calls, removed:** `Outbox::for_profile` (host locator outbox),
  `Controller::generation` (replica copy), `Session::active` (gateway control),
  `Worker::adopt_session` (network). Each was checked against the tests first.
- **Code only tests call, now `#[cfg(test)]`** so it is no longer in the shipped
  binary: `credential_vault::save` and `encode`, `Outbox::settle`,
  `route_choice::decide` and `Job::start`, `handover_locator::seal` (server),
  `Controller::running` with `Active::choice` (replica copy), and the two geometry
  fields `choosers` and `button` of the recovery help's `Drawn` with the code that
  fills them.
- **Real simplifications:** `?` instead of an identity `match` (host route), the
  map entry API (voice mesh), `contains` (takeover), `is_multiple_of`, a `c"main"`
  literal, `async fn`, `slice::from_ref` instead of cloning into a one-element
  array, `if let` instead of `is_some()` then `unwrap()` (local voice gateway),
  `expect_err`, `!is_empty()`, a type alias for two nested types, removing needless
  `&`.
- **Layout:** the four client files with code after their `#[cfg(test)]` module
  now have the tests last (`handover_ui`, `invitation_ui`,
  `network_local_lifecycle`) or the trailing item moved above them
  (`handover_runtime`, `handover_target` in the server). Moved blocks are unchanged.
- **Struct update syntax** in tests that built a `Default` value and then assigned
  fields (`JoinFlow`, `Bootstrap`).
- **One shared module:** `data_privacy.rs` was loaded twice with `#[path]` by
  `handover_target.rs` and `replica_agent.rs` (two copies of the Windows ACL code in
  one crate). `lib.rs` now declares it once and both use `crate::data_privacy`.
  The server binary keeps its own `mod data_privacy;` (a separate crate).
- **A guard held across an await** in a server test: the database guard now lives
  in a block that ends before the first `.await` (previously `drop(db)`, which the
  lint does not accept).
- **Compile-time limit checks:** the three constants in the gateway broker's
  `limits_match_the_data_plane` test are checked with inline `const { assert!(..) }`.

## Every `allow` added

No crate-level allows. Each is on one item with a comment saying why.

| where | lint | reason |
| --- | --- | --- |
| `relay-protocol/src/handover.rs` `ExportStatus` | `large_enum_variant` | A wire type, one value per export; boxing the manifest would change every construct and match site in the client and server for no gain. |
| `relay-protocol/src/handover.rs` `TargetCommand` | `large_enum_variant` | One command per companion call over a pipe; boxing the large variants would change every construct and match site. |
| `relay-server/src/takeover_inflight.rs` `Phase` | `large_enum_variant` | A few per takeover, never in bulk; boxing would add an allocation to every serde round trip of the write-ahead record. |
| `relay-server/src/takeover_signer.rs` `actual_capture_quorum` | `too_many_arguments` | Test fixture; every input is a distinct piece of the scenario. |
| `relay-client/src/handover_client.rs` `Action` | `large_enum_variant` | One value per user action; boxing would touch every construct and match site. |
| `relay-client/src/handover_client.rs` `spawn` | `too_many_arguments` | The eight values travel together into one worker thread. |
| `relay-client/src/handover_runtime.rs` `start_server` | `too_many_arguments` | Each argument is a distinct handle or secret for the child process launch. |
| `relay-client/src/network_account_login.rs` `account_login_begin` and `account_login_finish` | `too_many_arguments` | One argument per field of the login command each serves. A parameter struct would change the sign-in path that other work is editing. |
| `relay-client/src/invitation_ui.rs` `SetupAction` | `large_enum_variant` | One value per click on the setup form. |
| `relay-client/src/media.rs` `AudioCommand` | `large_enum_variant` | Sent a few times per call (start, stop, tone), never per audio frame. |
| `relay-client/src/network.rs` `Command` | `large_enum_variant` | One per user action on the worker channel. |
| `relay-client/src/replica_copy.rs` `work` | `too_many_arguments` | Thread entry point; each value is a distinct handle moved into the thread. |
| `relay-client/src/host_locator_renewal.rs` `Advance::Queued::more` | `dead_code`, only outside tests (`cfg_attr(not(test), allow(dead_code))`) | The field is part of the documented result of `advance` and is asserted by the renewal tests; the shipped caller does not read it. |

Candidates for a later change (not required for the gate): box the large enum
variants and give the sign-in functions a parameter struct, once the sign-in work
is merged.
