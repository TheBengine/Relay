## Decisions taken without asking (as instructed)

- `C:\Important\Projects\DESIGN.md` and `PRODUCT.md` describe another product (Agentic OS: Outfit,
  glass, indigo/cyan gradients). Relay keeps its own Discord-parity theme tokens; only the craft rules
  were applied (AA contrast, no glows, no side-tab borders, no monotonous card stacks).
- The black stage is used in the dark themes (Dark, Onyx, Ash). The light theme keeps its page colours,
  because the sound check and route controls on the page are drawn in theme colours.
- The camera preview opens when the camera dialog opens (Discord's default "Always preview video").
  The user already asked for the camera by clicking it; others see nothing until Turn On Camera.
- Thumbnails use GDI (`StretchBlt` for displays, `PrintWindow` for windows) on a worker thread in a new
  module, so Worker N's `capture.rs` / `graphics_capture.rs` are untouched. Windows that ask not to be
  captured (display affinity), minimised windows and GPU-only windows show "No preview for this window".
- Full Screen in the call bar makes the Relay window full screen (sidebars stay); Discord's call-only
  full screen would need `main_view.rs` layout changes.
- Accessible names changed to Discord's wording: "Turn On Camera", "Share Your Screen", "Stop Sharing",
  "Mute"/"Unmute", "Disconnect". No test or script referred to the old names.

## Left out

- Camera background (blur/replace): there is no settings field for it, so no option was added.
- Discord's Activities and Soundboard buttons: no such features.
- Discord's chat toggle in the voice channel header and a call-only full screen (`main_view.rs`).
- The pop-out window is not in the screenshots (the capture saves the main window); the
  `stream-popout` capture case opens it and passed without errors.
- Live thumbnails were checked on this PC with the ignored test
  `share_thumbnails::tests::a_real_display_gives_a_fitting_thumbnail` (no pixels saved); the screenshots
  use generated thumbnails.
- Not clicked through by hand in a two-person call: Watch Stream connecting video, Go Live with a real
  window, Turn On Camera with a real camera. These paths call the same functions as before
  (`request_video_connection`, `start_capture`, `stop_capture`).
