# Reviewed local SFU security build

The `.5` correction preserves the authenticated signing-key ID when refreshing
participant tokens. RTC and WHIP entrypoints bind the verified middleware value;
internal routing retains it separately from mutable user attributes. Refreshes
use that exact configured key. Unknown/revoked bindings fail closed; legacy
sessions may fall back only when one usable key is configured. Gateway signature
and issuer checks are unchanged. Five focused test groups and both offline
Windows/Linux builds pass. The package fetch pin now matches this recipe.
The `.5` Linux component is installed on the named Debian host; community and
Friends containers were retained. The fresh native attempt stopped before
account/media creation: Windows refused the resolved login connection with
WSA 10013. This is not proof of recovered native media or WAN acceptance.
[Actual deployment and native preflight limit](../../docs/evidence/friends-sfu-refresh-issuer-live-20261022.json).
[Scoped `.5` build receipt](../../docs/evidence/friends-sfu-refresh-issuer-build-20261022.json).

The `.4` correction fixes explicit local node selection on hosts with multiple
network interfaces. Existing host-address rewriting could collapse several
bound UDP sockets into one advertised candidate and keep an arbitrary socket.
The SFU now stably prioritizes an already-bound socket whose IP exactly matches
the explicit node. It does not add sockets, bypass explicit IP/interface filters,
change ports, or alter TURN permissions. External/autogenerated node handling is
unchanged. A deterministic two-socket ICE regression reproduces the old timeout,
then connects and exchanges synthetic datagrams both ways with the correction.
Four focused unit groups and both offline builds pass. This remains distinct
from actual native Friends/WAN acceptance.
[Scoped `.4` build receipt](../../docs/evidence/friends-sfu-local-node-mux-build-20261022.json).

The `.3` supplement distinguishes STUN binding requests/successes/errors in
each UDP direction and classifies reply sources as loopback, configured node IP
or other. It inspects only the bounded STUN header and retains no payload or
source address in the snapshot. This responds to the actual `.2` observation:
307 UDP writes succeeded and eight datagrams returned, with no permission or
local-port policy denial. Those reads alone are not proof of successful ICE
responses. The same loopback-only route now uses schema 2. Three observation
subcases, the actual TURN forwarding/reply test, both builds and the compiled
HTTP route pass. [Scoped `.3` build receipt](../../docs/evidence/friends-sfu-reply-observation-build-20261022.json).

The second 22 October supplement adds process-local TURN permission, UDP write
and UDP read counters, plus the effective local media-port ranges. The existing
API listener exposes `GET /relay/turn-status` only to its actual loopback TCP
peer; forwarded headers do not grant access, and other methods are refused.
The snapshot contains no addresses, room/user IDs, credentials or packet data.
These approximate cumulative counters observe the existing policy and packet
path without widening its decisions or opening a listener. Two focused service
tests (including two observation subcases), Windows/Linux builds and an actual
compiled loopback HTTP check pass. The version is
`1.13.10-relay-media.20261022.2`; Debian activation and live media acceptance are
separate. See [the scoped build receipt](../../docs/evidence/friends-sfu-observation-build-20261022.json).

The 22 October supplement adds an explicit `turn.external_tls_port` for the
named TLS-terminating proxy. Omission preserves the upstream advertisement on
443; an explicit valid port changes only the advertised address. Invalid ports,
missing listeners and a disabled/non-external TURN setup fail before listeners
start. The room manager uses this same validated address in its normal join
response. Dependencies and the Go 1.27.3 security baseline remain unchanged.
Two focused config tests and both Windows/Linux cross-builds passed locally.
That `.1` component was subsequently installed on the named Debian host. Its
native call still times out; relay allocation succeeds but ICE receives no
responses. See [the actual native failure evidence](../../docs/evidence/friends-ice-diagnostics-20261022.json).

This rebuild also addresses [GO-2026-6809](https://vuln.go.dev/ID/GO-2026-6809.json),
which adds distrust for compromised intermediate certificates. The earlier
Go 1.27.2 binary hash is superseded; it is not accepted by fetch-sfu.ps1.

The official Windows LiveKit 1.13.7 and 1.13.10 binaries still match Go/HTTP2
advisories. Do not restore either as an automatic fallback in a new Relay build.
This directory records a small source patch to the signed upstream 1.13.10
commit. It changes the Go minimum to 1.27.3, x/net to 0.60.0, checksums, and the
displayed version to `1.13.10-relay-security.20261021.2`. No media code changes.

`recipe.json` pins the upstream commit/archive, all six patches, patched files, Windows
binary and Apache license. Use the local handoff's `prepared-sfu` directory as
`scripts/fetch-sfu.ps1 -CacheDirectory`; both file hashes are checked before
publication. The script only prepares build output; it does not stop or install
an application. An existing verified output can be reused. Missing or mismatched
inputs fail without downloading the older binary.

To reproduce, verify the upstream archive hash, extract regular files into an
empty owned local directory, then use `git -c core.autocrlf=false apply` with
`livekit-1.13.10.patch` there, preserving LF source bytes. Check the
patched file hashes against the recipe. Apply `friends-turn-port-20261022.patch`
after the security patch, followed by `friends-turn-observation-20261022.patch`
and `friends-turn-reply-observation-20261022.patch`, then
`friends-local-node-mux-20261022.patch`, then
`friends-refresh-issuer-20261022.patch`,
also preserving LF bytes. Compare the final patched-file hashes in the recipe.
Use the official Go 1.27.3 Windows
amd64 compiler, CGO_ENABLED=0, GOOS=windows, GOARCH=amd64, and explicit local
module/build/temp caches. Prepare the public modules via proxy.golang.org with
sum.golang.org verification. Disable hidden Go configuration, workspaces,
external cache programs, telemetry and VCS fetching. Build with the recipe's
exact arguments, GOTOOLCHAIN=local and GOPROXY=off; compare the result hash before
using it. A newer compiler changes the binary hash and needs a fresh review/pin.

The checked binary matched only the unused OpenPGP module advisory. The actual
server import graph does not include that package. Generated video and stereo
audio passed through the actual local SDK/SFU. This is not WAN, physical-device,
listening-quality acceptance. This paragraph describes the original security
baseline; later Windows/Linux builds and the actual Debian `.5` cutover are
recorded by the supplement receipts above. Native recovery remains unaccepted.
